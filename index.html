🔎 Filtering with Boolean Masks

A mask is just a list of True/False values — one per row. When you write df["Volume"] > 150_000_000, pandas checks each row and returns True if that row's Volume exceeds 150M, False otherwise.

Then you pass the mask back into df[mask] and pandas returns only the True rows. You can store the mask first or do it in one line.

You can also compare strings: since dates are stored as "YYYY-MM-DD" strings, comparisons like df["Date"] >= "2025-12-01" work alphabetically — and luckily, alphabetical and chronological order match for that format!

📐 Aggregations

Aggregations collapse many values into one summary number. Examples: df["Close"].mean() gives the average closing price, df["Volume"].max() gives the single highest volume day.

The clever trick: a boolean mask is just a column of True and False. Since True == 1 and False == 0, calling .sum() on a mask counts how many rows are True. And to narrow a mask to a specific period, you can filter the mask's index: mask.index.to_period("Q") converts each date to its quarter label like "2025Q3".

🔄 Sorting and Removing Duplicates

Why sort? If dates are out of order, any rolling calculation (like a moving average) will be wrong. We first convert the Date column with pd.to_datetime() — this turns a text string like "02/01/2026" into a real date Python can sort and compare. The option dayfirst=True tells pandas the format is DD/MM/YYYY, not MM/DD/YYYY.

Why copy? df = df_raw.copy() creates a completely independent copy of the data. Without it, changes to df would silently modify df_raw too — always copy before cleaning.

Two ways to change a DataFrame — you need to recognise both. Most pandas methods build a new DataFrame and hand it back, leaving the original untouched. So the change only sticks if you catch the result:

df = df.sort_index()  — re-assign. The method returns the sorted DataFrame; df = points the name at it.
df.sort_index(inplace=True)  — in place. The method edits df directly and returns None. No df =, because there is nothing to catch.

Both leave df sorted. Most cleaning methods accept the argument — sort_index, set_index, drop, drop_duplicates, fillna, reset_index, rename — and you will meet inplace=True constantly in older notebooks and on Stack Overflow, which is why it is worth being able to read.

Which to use: re-assign. Three reasons. It chains — df.drop_duplicates().sort_index() reads as one pipeline, while the inplace versions cannot chain at all, because each one returns None and you would be calling .sort_index() on nothing. It fails loudly — the classic bug is writing df = df.sort_index(inplace=True), mixing the two styles, which quietly sets df to None and breaks every cell below with a baffling error. And it is the way pandas is going: inplace is being deprecated, so code written with it today will start raising warnings.

It does not even save memory, which is the usual justification — pandas generally builds the new object internally either way. So: know it when you read it, and re-assign when you write it. The exercise after this one lets you try both.

Why remove duplicates? If the same date appears twice, averages and sums will be inflated. drop_duplicates() keeps the first occurrence of any repeated row and removes the rest.

🩹 Handling Missing Values

Different columns need different fill strategies depending on what the value means:

• Close → ffill().bfill(): forward fill uses the last known value (yesterday's close). backward fill is chained after as a safety net — if the very first row is NaN, ffill has nothing to pull from, so bfill grabs the next known value instead.
• Volume → fillna(df["Volume"].median()): replace missing volume with the median (middle value) of all volumes. Median is safer than mean here because volume has spikes that would skew the average.
• Open → interpolate(method='linear'): estimates the missing value as a straight line between the values before and after it. For example, if Open was 100 on Monday and 106 on Wednesday, the missing Tuesday gets 103.
• High → df[["Close","Open"]].max(axis=1): axis=1 means "take the max across columns" (left to right) rather than down rows. This gives the higher of the two prices for each row individually — High must be at least the highest price seen that day.
• Low → High * 0.97: a simple approximation — if we have no Low data, assume it was 3% below High. This is a reasonable stand-in for a missing value.

# .bfill(): chained after as a fallback — catches the very first row if it's NaN (nothing before it to forward-fill)

df['Low'] = df['Low'].fillna(df['High'] * 0.97)
# approximate: assume Low was 3% below High — a simple but reasonable stand-in

df.isnull().sum()  # verify: every column should now show 0 missing values

📈 Buy & Hold Returns

The simplest investment strategy is buy & hold: buy a stock on a given date, hold it, and sell later. Your return is:

return = (sell_price − buy_price) / buy_price × 100

Two new tools you'll use here:

• df.loc['2026-01'] — when your index is dates, you can slice using a string. '2026-01' means "all rows in January 2026". '2026-03' means all of March, and so on. This only works because we set Date as the index and converted it to datetime.
• .iloc[0] and .iloc[-1] — iloc stands for "integer location". It selects rows by their position number, not by their label. iloc[0] is the very first row; iloc[-1] is the last row. iloc[-2] would be second-to-last, and so on.
• f'Buy price: ${buy_price:.2f}' — the :.2f inside curly braces is a format code: it rounds the number to 2 decimal places and displays it as a float. .0f would give zero decimals, .4f would give four.

🧹 Clean Your File

Your firm's cleaning rules for this sector, and the reasoning behind each one:

Forward fill missing Open/Close. A price that did not print is best approximated by the last price that did. ffill() never looks into the future, which matters — filling a price with tomorrow's value would leak information a real trader could not have had.

Interpolate missing High/Low. Highs and lows drift smoothly with the price, so a straight line between the day before and the day after is a fair guess. interpolate() needs a value on both sides of the gap.

Fill missing Volume with the median. Volume is wildly skewed — a few enormous days drag the mean upward, so the median is the more honest "typical day".

You also need to handle sorting, duplicates, and the two junk columns (Dividends, Stock Splits) — same as Session 2a.

The High that will not fill. If you drew MCD, interpolate() leaves one High still missing — it sits on the very first row, and interpolation needs a value on both sides of a gap. There is no "correct" fix, only trade-offs, and this is exactly the kind of call you will be asked to defend:

📐 Why Log Returns?

Log returns add up; simple returns do not. Gain 10% then lose 10% and you are not flat — you are down 1%, because the second move applies to a larger base. Simple returns have to be compounded: (1 + r).prod() - 1. Log returns can simply be summed: .sum(). That one property is why almost every quant model works in log space.

Two ways to accumulate, matching the two return types. For log returns use .cumsum() — a running total. For simple returns use (1 + r).cumprod() - 1 — a running product, since each day multiplies the previous wealth.

To convert a log return back to a simple one, undo the logarithm: np.exp(log_return) - 1. np.exp() is the inverse of np.log().

📈 Buy & Hold

With a CumulativeReturn column in place, any buy-and-hold question becomes a lookup. Because the column is a running total from the first day, the value on any date is your return from the start of the data to that date.

Buying part-way through is different: you need the return accumulated between two dates, not from the beginning. Slice the period first, then compound only those rows.

The off-by-one that matters. These are close prices. If you buy at the close on 1 April, you did not earn 1 April's return — that move happened before you owned it. Your first return is 2 April's. Getting this wrong flatters every backtest you will ever write, so slice from the day after you buy.

🎚 Moving Averages

A moving average smooths a noisy price into a trend. df["Close"].rolling(20).mean() slides a 20-row window down the column and averages whatever sits inside it, so each point is the mean of that day and the 19 before it.

The window length is the whole trade-off. A fast average (20 days) hugs the price and turns quickly, but whipsaws on noise. A slow one (120 days) ignores noise and shows the underlying trend, but turns long after the move began. Neither is right — they answer different questions, and Session 8 builds a trading strategy out of exactly that tension.

The first rows come back as NaN, and that is correct: a 120-day average genuinely does not exist until day 120. Matplotlib simply leaves that stretch of the line blank.

Regression

Correlation says two things move together. Regression puts a number on it — how much of one is explained by the other, and whether that relationship is strong enough to believe. This session covers fitting an OLS model with statsmodels and reading the output properly.

📉 Fitting an OLS Model

statsmodels is the library for statistical modelling, and it loads on first use like seaborn. OLS — ordinary least squares — fits the straight line minimising the squared vertical distance to every point.

The line is y = α + βx. Your response y is what you are explaining; your predictor x is what you are explaining it with. In sm.OLS(y, X) the response comes first — swap them and you fit a different model that answers a different question.

You must call sm.add_constant(X). Without it statsmodels fits y = βx with no intercept, forcing the line through the origin and biasing β. It is the single most common mistake with this library, and nothing warns you.

Fit with .fit(), then read .summary().

🔍 Reading the Output

coef on your predictor is the slope β: a one-unit move in x is associated with a β move in y. Between two stocks' returns this is a beta in the finance sense — how much Google moves for a given Apple move. The const coefficient is α, the intercept.

R-squared is the share of variance in y explained by x, from 0 to 1. On daily stock returns anything above roughly 0.3 is a strong relationship — these are noisy series, and expecting the 0.9 you see in a textbook is a misunderstanding of the data, not a failure of the model.

P>|t| is the p-value: the probability of seeing a coefficient this large if the true relationship were zero. Below 0.05 is the conventional threshold for "statistically significant".

And the warning worth repeating: this is association, not causation. Apple returns do not cause Google returns. Both are technology stocks responding to the same market and sector news, which is precisely the shared factor structure you saw in the Session 6 heatmap.

Trading Strategies

Everything so far has described the past. A strategy takes a position on the future: a rule that turns prices into signals, signals into positions, and positions into a return you can compare against simply holding the stock.

⚔️ Moving Average Crossover

The pipeline has four stages, and the order matters. A signal is what the rule says today: +1 long, −1 short, 0 flat. A position is what you actually hold, which is the signal shifted forward one day. A strategy return is position × the market return that day. Compound those and you have a cumulative return to put next to buy-and-hold.

Why the shift is the whole game. You compute today's signal from today's close — which you do not know until the market has shut. You can only act on it tomorrow. Position = Signal.shift() encodes that one-day delay. Leave it out and your backtest trades on information it could not have had, and the returns it reports are fiction. This is look-ahead bias, and it is the single most common way a backtest lies to you.

np.where(condition, a, b) is a vectorised if/else: a where the condition holds, b where it does not, applied to the whole column at once.

Setup

import numpy as np
import matplotlib.pyplot as plt

df['Market']   = (1 + df['MarketDaily']).cumprod() - 1

Find the crossover dates

On which dates did the signal actually flip? The signal only ever holds +1 or −1, so a change from one to the other is a jump of 2.

In [ ]
Show Solution

df[abs(df['Signal'].diff()) == 2]
# .diff() gives today minus yesterday: +1 → -1 is -2, and -1 → +1 is +2
# abs() catches both directions at once; anything else is 0 (no change)

Your strategy lost to buy-and-hold. That is the correct answer, not a bug. META ran from roughly $135 to $620 over this period. The crossover rule holds -1 — a short position — every time the fast average sits below the slow one, and shorting a stock that quadruples is about as expensive as trading gets. Expect the strategy to finish far behind the market here, and do not go hunting for the mistake.

Three things are actually going on. Shorting in a bull market does the damage: change the signal to np.where(fast > slow, 1, 0) so you are either long or flat, and the result improves immediately. Whipsaw costs you on top of that — every crossover in a sideways stretch is a round trip that pays nothing. And this backtest charges no transaction costs, which flatters it: add a realistic fee per trade and most crossover strategies get worse, not better.

The honest summary is that a moving average crossover is a trend-following rule. It is designed to give up upside in exchange for getting out of sustained declines, so it tends to lose to buy-and-hold in a straight bull run and earn its keep in a drawdown. Judging it on one stock over one favourable period tells you very little either way — which is precisely why the last lesson in this session is about testing many parameters rather than trusting one.

📊 Bollinger Bands

Bollinger Bands wrap a moving average in a channel two standard deviations wide: SMA ± 2 × rolling std. Because the width is driven by recent volatility, the channel widens in turbulent markets and narrows in calm ones.

Two opposite strategies read the same bands. Mean reversion says a touch of the upper band is overbought — sell it, expecting a snap back. Breakout says the opposite: a close above the upper band is strength confirming itself — buy it. The exercise below implements the breakout reading.

The pattern for holding a position between signals is worth learning on its own: set the signal only on the days the rule fires, leave every other day as np.nan, then ffill() to carry the last signal forward until the next one replaces it. fillna(0) finally flattens the stretch before the first signal ever fires.

🎛 Parameter Optimisation

Any strategy with a window size has arbitrary numbers in it. 50 and 200 are convention, not science. Testing a grid of combinations is how you find out whether the rule works or whether you simply picked lucky numbers.

An EMA — exponential moving average, .ewm(span=n, adjust=False).mean() — weights recent prices more heavily than old ones, so it reacts faster than a simple average of the same length.

Two nested for loops give you every combination: the outer loop runs once per fast window, and for each of those the inner loop runs through every slow window.

Read the result with suspicion. Testing nine combinations and reporting the best one is not evidence the strategy works — with enough combinations something always looks good on one sample. The honest test is whether the winner still wins on a period you did not use to choose it. That is the difference between a backtest and a discovery.

Portfolios & Optimisation

Nobody holds one stock. This session builds a portfolio from several, measures its risk-adjusted return with the Sharpe ratio, and then solves for the weights that maximise it.

🧺 Building a Portfolio

A portfolio is several securities held together, each with a weight — the share of your money in it. Weights sum to 1. A 1/N or equal-weighted portfolio simply splits the money evenly, and it is a much harder benchmark to beat than it looks.

The portfolio return on any day is the weighted average of the individual returns. returns.dot(weights) does that in one step: the dot product multiplies each stock's return by its weight and sums across the row, giving one portfolio return per day.

.isin(list) filters rows whose value appears anywhere in a list — the clean way to pull a handful of tickers out of a panel without chaining a dozen | conditions.

⚖️ The Sharpe Ratio

Return alone is not a result — you can always get more of it by taking more risk. The Sharpe ratio asks how much excess return you earned per unit of volatility:

Sharpe = (Rp − Rf) / σp, where Rp is the annualised portfolio return, Rf the risk-free rate, and σp the annualised volatility.

Subtracting Rf matters: a portfolio returning 4% when Treasury bills pay 4.5% has earned nothing for the risk it took, and its Sharpe is negative. Loosely, above 1 is good, above 2 is very good, and anything above 3 on a backtest is usually a bug, a look-ahead leak, or a period too short to mean anything.

🎯 Optimising the Weights

Equal weights are arbitrary. scipy's minimize searches for the weights giving the best Sharpe — it loads on first use like the other heavy libraries.

minimize only ever minimises, so to maximise Sharpe you minimise negative Sharpe. That sign flip is the standard trick and the easiest thing to get wrong.

Two things keep the answer sensible. A constraint that weights sum to 1 keeps you fully invested, and bounds of (0, 1) per weight forbid short positions. Drop the bounds and the optimiser will happily propose shorting one stock 300% to fund another.

The catch worth stating plainly. These weights are optimal for the period you fitted them on, and they are fitted to estimates of return and covariance that are themselves noisy. Out of sample, optimised weights routinely lose to 1/N. What follows is how the machinery works — not a recommendation to trade it.

from scipy.optimize import minimize               # loads on first use — one-off pause

def neg_sharpe(weights, returns, rf):
    port = returns.dot(weights)                     # daily portfolio returns for these weights
    r = port.mean() * 252
    v = port.std() * np.sqrt(252)
    return -(r - rf) / v                            # NEGATIVE, because minimize() only minimises

n = len(tickers)
constraints = {'type': 'eq', 'fun': lambda w: np.sum(w) - 1}
# 'eq' means this expression must equal zero, i.e. the weights must sum to exactly 1
bounds = tuple((0, 1) for _ in range(n))
# each weight between 0 and 1 — no shorting, no leverage

result = minimize(neg_sharpe, init_weights, args=(returns, risk_free_rate),
                  method='SLSQP', bounds=bounds, constraints=constraints)
# SLSQP is the standard method when you have both bounds and constraints
# init_weights is the starting guess; args passes the extra inputs through to neg_sharpe

optimal_weights = result.x                          # .x holds the winning weight vector
print('Optimal weights:')
for t, w in zip(returns.columns, optimal_weights):
    print(f'  {t:5} {w:6.1%}')
print(f'\nMaximum Sharpe: {-result.fun:.3f}')       # flip the sign back to read it as a Sharpe
print(f'Versus 1/N:     {sharpe_ratio:.3f}')
