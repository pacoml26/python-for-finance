🔎 Filtering with Boolean Masks

A mask is just a list of True/False values — one per row. When you write df["Volume"] > 150_000_000, pandas checks each row and returns True if that row's Volume exceeds 150M, False otherwise.

Then you pass the mask back into df[mask] and pandas returns only the True rows. You can store the mask first or do it in one line.

You can also compare strings: since dates are stored as "YYYY-MM-DD" strings, comparisons like df["Date"] >= "2025-12-01" work alphabetically — and luckily, alphabetical and chronological order match for that format!

📐 Aggregations

Aggregations collapse many values into one summary number. Examples: df["Close"].mean() gives the average closing price, df["Volume"].max() gives the single highest volume day.

The clever trick: a boolean mask is just a column of True and False. Since True == 1 and False == 0, calling .sum() on a mask counts how many rows are True. And to narrow a mask to a specific period, you can filter the mask's index: mask.index.to_period("Q") converts each date to its quarter label like "2025Q3".

Original · Apple Quarters

Q3 vs Q4: above-average close days

Did Q3 or Q4 2025 have more trading days where Close was above the annual average? Create a mask for above-average close, then count how many days in Q3 and Q4 satisfy it.

In [ ]
Show Solution 
mask = df['Close'] > df['Close'].mean()  # True for days where Close beats the full-year average

# ── Approach 1: slice the mask by date range (simplest) ──
q3 = mask.loc['2025-07':'2025-09']       # a mask keeps the date index, so .loc slices it like any Series
q4 = mask.loc['2025-10':'2025-12']       # with .loc BOTH ends are included, unlike normal Python slicing
print('Q3', q3.sum())                    # .sum() counts the Trues, because True == 1 and False == 0
print('Q4', q4.sum())

# ── Approach 2: match on the quarter label ──
quarters = mask.index.to_period('Q')     # turns each date into its quarter: 2025-08-14 → '2025Q3'
print('Q3', mask[quarters == '2025Q3'].sum())
print('Q4', mask[quarters == '2025Q4'].sum())
# comparing quarters to a string gives a second mask, used here to filter the first one
# more typing than approach 1, but it survives a change of year — no hard-coded month boundaries

🔬 Inspecting for Problems

To count missing values in every column at once, chain two methods: df.isnull() creates a DataFrame of True/False (True = missing), then .sum() adds up the Trues in each column. This is called method chaining.

Common problems to look for: Non-null count < total rows means missing values. Columns you don't need (Dividends, Stock Splits) waste memory. Dates unsorted or duplicated will break time-series calculations.

🔄 Sorting and Removing Duplicates

Why sort? If dates are out of order, any rolling calculation (like a moving average) will be wrong. We first convert the Date column with pd.to_datetime() — this turns a text string like "02/01/2026" into a real date Python can sort and compare. The option dayfirst=True tells pandas the format is DD/MM/YYYY, not MM/DD/YYYY.

Why copy? df = df_raw.copy() creates a completely independent copy of the data. Without it, changes to df would silently modify df_raw too — always copy before cleaning.

What is inplace=True? Most pandas methods return a new DataFrame and leave the original unchanged. Adding inplace=True modifies the DataFrame directly, so you don't need to write df = df.sort_index() — it just happens. Both styles are equivalent; inplace=True saves a line.

Why remove duplicates? If the same date appears twice, averages and sums will be inflated. drop_duplicates() keeps the first occurrence of any repeated row and removes the rest.

Original

Sort by date and drop duplicates

The Date column uses day-first format (DD/MM/YYYY), so you must tell pandas dayfirst=True when converting. Then set it as the index using set_index("Date", inplace=True), sort with sort_index(inplace=True), and drop duplicates. Store the cleaned result in df.

In [ ]
Show Solution 
df = df_raw.copy()                                       # make an independent copy — changes to df won't touch df_raw
df['Date'] = pd.to_datetime(df['Date'], dayfirst=True)   # convert text dates to datetime; dayfirst=True because format is DD/MM/YYYY
df.set_index('Date', inplace=True)                       # make Date the row index; inplace=True modifies df directly (no reassignment needed)
df.sort_index(inplace=True)                              # sort rows oldest → newest by their date index

🩹 Handling Missing Values

Different columns need different fill strategies depending on what the value means:

• Close → ffill().bfill(): forward fill uses the last known value (yesterday's close). backward fill is chained after as a safety net — if the very first row is NaN, ffill has nothing to pull from, so bfill grabs the next known value instead.
• Volume → fillna(df["Volume"].median()): replace missing volume with the median (middle value) of all volumes. Median is safer than mean here because volume has spikes that would skew the average.
• Open → interpolate(method='linear'): estimates the missing value as a straight line between the values before and after it. For example, if Open was 100 on Monday and 106 on Wednesday, the missing Tuesday gets 103.
• High → df[["Close","Open"]].max(axis=1): axis=1 means "take the max across columns" (left to right) rather than down rows. This gives the higher of the two prices for each row individually — High must be at least the highest price seen that day.
• Low → High * 0.97: a simple approximation — if we have no Low data, assume it was 3% below High. This is a reasonable stand-in for a missing value.

Original · Cleaning Up

Fix each column's missing values

Apply the appropriate fill strategy to each column. After filling, verify with df.isnull().sum() that all missing values are gone.

In [ ]
Show Solution 
df['Close'] = df['Close'].ffill().bfill()
# ffill(): replace NaN with the most recent previous value (yesterday's close)
# .bfill(): chained after as a fallback — catches the very first row if it's NaN (nothing before it to forward-fill)

df['Volume'] = df['Volume'].fillna(df['Volume'].median())
# fillna(): replace NaN with a specific value; median() = the middle value when sorted — robust against extreme spikes

df['Open'] = df['Open'].interpolate(method='linear')
# interpolate(): estimate missing values as a straight line between the known values on either side

df['High'] = df['High'].fillna(df[['Close', 'Open']].max(axis=1))
# df[['Close','Open']] selects two columns; .max(axis=1) takes the larger of the two for each row individually
# axis=1 means "across columns" (left to right); axis=0 would mean "down rows"

df['Low'] = df['Low'].fillna(df['High'] * 0.97)
# approximate: assume Low was 3% below High — a simple but reasonable stand-in

df.isnull().sum()  # verify: every column should now show 0 missing values

📈 Buy & Hold Returns

The simplest investment strategy is buy & hold: buy a stock on a given date, hold it, and sell later. Your return is:

return = (sell_price − buy_price) / buy_price × 100

Two new tools you'll use here:

• df.loc['2026-01'] — when your index is dates, you can slice using a string. '2026-01' means "all rows in January 2026". '2026-03' means all of March, and so on. This only works because we set Date as the index and converted it to datetime.
• .iloc[0] and .iloc[-1] — iloc stands for "integer location". It selects rows by their position number, not by their label. iloc[0] is the very first row; iloc[-1] is the last row. iloc[-2] would be second-to-last, and so on.
• f'Buy price: ${buy_price:.2f}' — the :.2f inside curly braces is a format code: it rounds the number to 2 decimal places and displays it as a float. .0f would give zero decimals, .4f would give four.

This section uses the cleaned 2026 DataFrame (df) you built in the previous exercises. Make sure you've run the cleaning cells above before starting.

Original · Buy & Hold

Part 1 — Quarterly returns

Imagine you had bought AAPL at the start of 2026 (first available trading day). What would your return have been if you sold at the end of March? And at the end of April? Print both results clearly.

In [ ]
Show Solution

# df.loc['2026-01'] → all rows in January 2026 (works because the index is datetime)
# ['Close']         → take the Close column from that slice
# .iloc[0]          → first row by position = first trading day of January

return_march = (sell_march - buy_price) / buy_price * 100  # standard return formula: gain / cost × 100

sell_april = df.loc['2026-04']['Close'].iloc[-1]  # last trading day of April
return_april = (sell_april - buy_price) / buy_price * 100

print(f'Buy price (Jan 2026):    ${buy_price:.2f}')   # :.2f = format as float with 2 decimal places
print(f'Sell end-of-March:       ${sell_march:.2f}  →  Return: {return_march:.2f}%')
print(f'Sell end-of-April:       ${sell_april:.2f}  →  Return: {return_april:.2f}%')

🧹 Clean Your File

Your firm's cleaning rules for this sector, and the reasoning behind each one:

Forward fill missing Open/Close. A price that did not print is best approximated by the last price that did. ffill() never looks into the future, which matters — filling a price with tomorrow's value would leak information a real trader could not have had.

Interpolate missing High/Low. Highs and lows drift smoothly with the price, so a straight line between the day before and the day after is a fair guess. interpolate() needs a value on both sides of the gap.

Fill missing Volume with the median. Volume is wildly skewed — a few enormous days drag the mean upward, so the median is the more honest "typical day".

You also need to handle sorting, duplicates, and the two junk columns (Dividends, Stock Splits) — same as Session 2a.

Step 2

Apply the cleaning rules

Build df from df_raw. Parse the dates, drop the junk columns, remove duplicates, set the date as index and sort it, then fill the gaps by the rules above. Finish by checking df.isnull().sum().sum() — read the note underneath before you assume zero is the only right answer.

In [ ]
Show Solution 
df = df_raw.copy()                               # .copy() — without the () you get the method, not a copy;
                                                 # without .copy() at all, df and df_raw stay the SAME object
df['Date'] = pd.to_datetime(df['Date'])          # text → real datetimes, so the index can slice by month later
df = df.drop(columns=['Dividends', 'Stock Splits'])
# columns= is required — df.drop(['Dividends']) looks for ROWS with those labels and raises KeyError
df = df.drop_duplicates()                        # removes rows that are byte-for-byte repeats of an earlier row
df = df.set_index('Date').sort_index()           # Date becomes the index, then oldest → newest

df[['Open', 'Close']] = df[['Open', 'Close']].ffill()
# double brackets select BOTH columns at once; ffill carries the last known price forward into each gap
df[['High', 'Low']] = df[['High', 'Low']].interpolate()
# straight-line estimate between the value before the gap and the value after it
df['Volume'] = df['Volume'].fillna(df['Volume'].median())
# median, not mean — a few huge volume days would drag a mean well above a normal day

print(f'Rows: {len(df_raw)} → {len(df)}')        # how many rows the cleaning actually removed
print(f'Missing values left: {df.isnull().sum().sum()}')
# .isnull() → True/False per cell; first .sum() → per-column counts; second .sum() → one grand total
df.head()
⚠️
Two things will not come out clean, and both are deliberate. Depending on your ticker you may still see a missing value, or a row count that did not fall as far as you expected. Do not paper over them — read the next two boxes.

The High that will not fill. If you drew MCD, interpolate() leaves one High still missing — it sits on the very first row, and interpolation needs a value on both sides of a gap. There is no "correct" fix, only trade-offs, and this is exactly the kind of call you will be asked to defend:

Fetch the true value from another source (best, if you can)  ·  drop the row (cleanest, costs you a day)  ·  floor it at max(Open, Close) (a High can never be below either, so this is the safest lower bound)  ·  backfill from the next day (accepts look-ahead bias)  ·  leave it as NaN and let downstream code skip it.

Whichever you pick, say which one you picked when you present. An unexplained number is worth less than an imperfect number with its reasoning attached.

The duplicate that survives. drop_duplicates() only removes rows that are identical across every column. If a repeated row later had a price go missing in one copy but not the other, the two are no longer identical and both stay. Same trap as Session 2a — catch it by checking the index instead:

df.index.duplicated().sum() counts dates appearing more than once, and df = df[~df.index.duplicated(keep='first')] keeps only the first row of each date.

Variation

Handle your leftovers

Check for both problems, then deal with whichever ones your ticker has. Print the before/after so your decision is visible.

# checks the INDEX for repeats — catches same-date rows that drop_duplicates() missed

                                                 # keep='first' → the earliest copy of each date wins

print('Still missing:\n', df.isnull().sum())     # per-column counts, so you can see WHICH column has the hole

# the floor-it option: a day's High can never be below its own Open or Close
# axis=1 → take the max ACROSS the two columns for each row (axis=0 would go down each column instead)

print('\nAfter:', df.isnull().sum().sum(), 'missing,', len(df), 'rows')

Q5

Did the year finish nearer the high or the low?

Take the final close and measure its distance to the year's best and worst close. A stock closing the year near its high has momentum behind it; one closing near its low does not.
